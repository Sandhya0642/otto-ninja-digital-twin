ROS 2 + MuJoCo integration

The web app is the experiment dashboard. Run the physics simulator and ROS 2 bridge on a compatible local Linux machine.

Deployment boundary: Vercel hosts this static dashboard. It does not run a persistent ROS 2 graph or local MuJoCo physics process. The files below are a starter scaffold that must be installed and tested locally.

01 · MuJoCo physics model

XML model for a simplified two-leg Otto-style robot with a floating base and actuated hip joints. Check geometry, inertia, contacts, and joint definitions before using it for scientific results.

mujoco/otto_ninja.xml

02 · ROS 2 command node

Starter Python node publishes a repeatable gait command signal. It is not yet a verified MuJoCo-ROS co-simulation bridge or physical-servo driver.

ros2_ws/src/otto_ninja_twin/

03 · Hardware interface

Replace the example publisher with the actual controller/firmware protocol and safety checks. Confirm servo ranges and emergency-stop behavior on the real robot.

docs/hardware_bridge.md

04 · Validation record

Log timestamps, commands, observed yaw/distance, battery state, calibration offsets, and environment so virtual and physical runs can be compared fairly.

docs/experiment_protocol.md

Local setup outline

  1. Install a compatible Ubuntu + ROS 2 distribution and Python environment.
  2. Install MuJoCo Python bindings using pip install -r requirements-mujoco.txt.
  3. Validate the XML model with the MuJoCo viewer before adding ROS control.
  4. Build the ROS 2 package with colcon build in your workspace.
  5. Implement and test the bridge, then compare logged measurements against the physical robot.

Thesis notes

A practical plan for turning this starter into a defensible M.Tech research project.

Proposed problem statement

Low-cost biped robots often exhibit differences between commanded motion and actual movement due to servo offsets, mechanical asymmetry, battery variation, and contact effects. This work will develop a simulation-assisted workflow for quantifying those differences and evaluate whether a repeatable calibration procedure improves turning and walking accuracy.

This is a hypothesis and project plan, not a claim of established novelty. Review related work and demonstrate the improvement experimentally before presenting it as a contribution.

Research objective

Build a simplified virtual model, define repeatable motions, measure physical behavior, and quantify the simulation-to-hardware mismatch.

Potential contribution

Low-cost calibration procedure for reducing measured turning or trajectory error, supported by baseline and post-calibration trials.

Minimum viable result

One validated task (e.g., 30° turn) with repeated trials, clear error metrics, baseline comparison, and transparent limitations.

Evidence to collect

Video or external tracking, servo command logs, repeatability data, calibration details, and a literature-based comparison.
